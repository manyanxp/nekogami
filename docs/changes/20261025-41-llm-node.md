# 2026-10-25 LLM ノード（rev2 の第 1 段階）

- 関連 ADR: 0040
- 関連要件: [rev2](../requirements/20261025-rev2-llm-node-tree-dynamic-agents.md)（1、3、4）
- 影響範囲: `dashboard/{llm-tools,server}.mjs`、`portal/backend/portal_api/{registry,definitions}.py`、`web/src/`（管理ページ）、`docker-compose.yml`

## 変更前
ローカル LLM は、別セッション型の委任先 `local-llm` としてだけあり、猫神さまだけが呼べた。ノードではなく、委任先の登録ダイアログには Claude のモデル選択が出ていた。

## 変更後
- ツールの種類に `llm` を追加。モデル名・システムプロンプト・温度・出力の長さを持つ。管理ページに「ローカル LLM」の追加ボタンと、編集パネル（プロンプトの編集欄つき）。
- 担当へつなぐと、`ask` ツールで質問できる（Ollama を直接呼ぶ）。つないだ担当だけが使える。
- ノードと委任先の登録ダイアログは、Claude のモデルではなく、ローカル LLM のモデル名を表示する。
- ディレクトリ・LLM のノードは、サブオーケストレーターにもつなげる。つなぐと、委任先（`azure-sage` なら `azure-architect`）の担当の定義に反映される。猫神さまなど、ツールを書けない担当には、つなげない（登録時に拒否）。
- 不具合の修正: 管理ページでサブオーケストレーターを選ぶと「定義ファイルを読めない: /project/CLAUDE.md」と出ていた（`api` コンテナにプロジェクト直下の `CLAUDE.md` が渡っていなかった）。マウントを足した。
- 検証: API 56 件、Console 42 件、画面 45 件が成功。実機で、Claude → 担当 → `ask` → Ollama の通しを確認した。

## 移行・注意点
- `docker compose up -d --build`。Ollama を使うなら `--profile local-llm`。接続先を変えるときは、`OLLAMA_URL`。
- 既存のディレクトリ・LLM のノードの、定義のない担当への接続（台帳だけで効いていなかったもの）は、そのまま残る。新しく足すときだけ拒否される。
