# 2026-10-25 ローカル LLM の担当（rev1 の第 4 段階）

- 関連 ADR: 0039
- 関連要件: [rev1](../requirements/20261025-rev1-ui-and-agent-tools.md)（B1）
- 影響範囲: `docker-compose.yml`、`nekogamisama/{bin/delegate.sh,suborchestrators.json,local-llm/}`、`portal/backend/portal_api/registry.py`

## 変更前
担当のモデルは、Claude（Haiku / Sonnet / Opus）に限られていた。

## 変更後
- `ollama` サービスを追加（プロファイル `local-llm`、GPU 利用、ポート非公開）。`qwen3:8b` を、RTX 3080（10GB）で動かす。
- 委任先 `local-llm`（別セッション型）を追加。`claude -p` を、Ollama の Anthropic 互換 API へ向けて実行する。読み取り専用。
- session 型の委任先に、許可リスト制の `env` と `args` を追加（`delegate.sh` と台帳の両方で検査）。
- 窓の指定（`CLAUDE_CODE_MAX_CONTEXT_TOKENS`）と `modelOverrides` で、モデル未認識の警告を消した。自動圧縮も 16K の窓で効く。
- 検証: API 54 件（`delegate.sh` の試験 3 件を含む）が成功。実機で、GPU・応答の速さ・ツール呼び出し・猫神さま経由の委任を確認した。

## 移行・注意点
- 使うとき: `docker compose --profile local-llm up -d ollama`、続けて `docker compose --profile local-llm exec ollama ollama pull qwen3:8b`。NVIDIA Container Toolkit が要る。
- 使わないときは、何も変わらない（`local-llm` の呼び出しが接続エラーになるだけ）。
- 文脈は 16K。長い作業には向かない（ADR 0039）。
- ライセンス台帳に Ollama・Qwen3 を追加した。
