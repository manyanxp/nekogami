# 要件資料: 猫神さま（NekoGamiSama）— Phase 2

- 元資料: [2026-10-24.add_requirement.md](../add_requirement/2026-10-24/2026-10-24.add_requirement.md) の「1.2 要求 Phase2」
- 日付: 2026-10-24 / 状態: 実装済み（初版）。実機での委任動作は未確認（§6）

## 1. 目的
Azure 専用だった構成の上に、全体を束ねる上位オーケストレーター「猫神さま」を置く。既存の Azure 調査エージェント群は変えずに、猫神さまのサブオーケストレーターとして位置づける。

## 2. 要求と対応

| # | 要求 | 対応 | 実装 / 決定 |
|---|---|---|---|
| P1 | 既存の Azure 調査エージェント群を残したまま、新しい上位オーケストレーターを作る | `.claude/`・`CLAUDE.md`・`dashboard/` の Azure Sage は無変更。猫神さまは別フォルダ `nekogamisama/` に作る | ADR 0011 |
| P2 | プロジェクト名は猫神さま（NekoGamiSama） | 猫神さまの定義は `nekogamisama/CLAUDE.md`。ポータルの表示名を「猫神さま Portal」に変更。リポジトリ名・既存ドキュメントの題名は据え置き | ADR 0011 |
| P3 | 猫神さまが全サブオーケストレーターとエージェントを管理する | 台帳に `suborchestrator` 種別を追加。最上位 `nekogamisama`（orchestrator）の配下に、サブオーケストレーターとエージェントを置く。サブオーケストレーターの一覧は `nekogamisama/suborchestrators.json` | ADR 0011, 0006 |
| P4 | 最初の Azure 調査エージェントを猫神さまのサブオーケストレーターにする | `azure-sage` を `suborchestrator`（親 = `nekogamisama`）に変更。UUID は変えず、Phase 1 の台帳は同期時に自動で移行する。4 サブエージェントは `azure-sage` の配下のまま | ADR 0011 |
| P5 | 各エージェントのトレースログに出る言葉の語尾に「にゃ」を付ける | Agent Console のサーバーが、エージェントの発言（最終メッセージ、サブエージェントの発話）の語尾に「にゃ」を付けてから配信する。環境変数 `NYA_SUFFIX` で変更・無効化 | ADR 0012 |

## 4. 制約と確認
- 新規ライブラリなし（Python 標準ライブラリ、Node 標準モジュール、シェルスクリプトのみ）。ライセンスの追加確認は不要。
- Claude Code の条件は NOTICE.md のとおり。委任先の実行も同じ利用条件に従う。

## 5. 範囲外・将来
- 範囲外: 猫神さまの下に Azure 以外のサブオーケストレーターを実際に作ること（登録の仕組みだけ用意した）。
- 将来: 委任の結果をポータルのトレースに親子として結び付ける、Docker で動くサブオーケストレーターへの委任（HTTP 経由）。
