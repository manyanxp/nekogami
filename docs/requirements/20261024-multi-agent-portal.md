# 要件資料: マルチエージェント管理ポータル

- 元資料: [2026-10-24.add_requirement.md](../add_requirement/2026-10-24/2026-10-24.add_requirement.md)
- 日付: 2026-10-24 / 状態: 実装済み（初版）

## 1. 目的
今後増えるオーケストレーター・エージェント・サブエージェントを一元管理し、Docker で動くエージェントを UI から起動・停止できるようにする。個人利用が前提。

## 2. 要求と対応

| # | 要求 | 対応 | 実装 / 決定 |
|---|---|---|---|
| R1 | 複数のオーケストレーター・エージェント・サブエージェントを追加したい | 台帳に種別（orchestrator / agent / subagent）と親子関係を持たせて登録 | ADR 0006 |
| R2 | 一覧管理したい | ポータルの一覧（親子ツリー表示、検索・種別フィルタ） | `web/` |
| R3 | UUID などで一意に管理したい | 登録時に UUID v4 を採番。組み込み分は UUID v5（再取り込みしても同じ ID） | ADR 0006 |
| R4 | 認証・認可（Agent 365 のイメージ）。個人利用なら不要で可 | **認証は不要と判断**。ローカル限定待受 + Host/Origin 検証で守り、任意で共有トークンを有効化できる。ロール型の認可は導入しない | ADR 0008 |
| R5 | 新しくポータル化した UI | `web/`（Next.js。http://127.0.0.1:4400）。既存の Agent Console はリンクで連携 | ADR 0007 |
| R6 | Docker コンテナ + Compose で追加し、UI から起動・停止したい | 台帳に compose ファイルとサービス名を登録し、`docker compose up -d / stop` を実行。状態も表示 | ADR 0009 |
| R7 | フロントとバックエンドのロジック分離 | `portal/backend`（REST API）と `web/`（`src/lib/api.ts` / `model.ts` ほか）。API は JSON のみで結合 | ADR 0007 |
| R8 | バックエンドは Python、フロントは現行言語 | Python 3.10+（標準ライブラリのみ）/ HTML + JavaScript（ES Modules） | ADR 0007 |

## 4. 制約と確認
- 使用ライブラリは商用利用可の寛容ライセンスのみ: ポータルの追加依存は **なし**（Python 標準ライブラリのみ）。
- 本体を MIT にしても問題ない根拠: 同梱する第三者コードは寛容ライセンスのみ。Claude Code / Agent SDK は同梱せず利用者が取得し、NOTICE に条件を明記。

## 5. 非機能・範囲外
- 範囲外: マルチユーザー、ロール型認可、エージェントのイメージのビルド、既存 Agent Console（Node）の Python 移行。
- 将来: Agent Console のトレース/チャットを複数オーケストレーターに対応させる、台帳の DB 化、ポータルのコンテナ化（Docker ソケットの扱いに注意）。

## 6. 受け入れ基準
1. エンティティを追加・編集・削除でき、すべてに UUID が付く。親子の整合性が検証される。
2. 組み込み（azure-sage と 4 サブエージェント）が自動登録される。
3. docker ランタイムのエンティティを UI から起動・停止でき、状態が表示される。
4. `PORTAL_TOKEN` 設定時、トークンなしの API 呼び出しは 401。
5. バックエンドのテストが通る。
