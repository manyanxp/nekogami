# 要件資料: トレースのターミナル化、UI アイコン、ローカル LLM・Python 実行・ディレクトリ権限（rev1）

- 元資料: `docs/add_requirement/2026-10-25/2026-10-25.add_requirement_rev1.md`（Git の管理対象外）
- 日付: 2026-10-25 / 状態: **第 1 段階（画面）と第 2 段階（ディレクトリのノード）が実装済み**。第 3・4 段階は未着手

## 1. 目的
ポータルの画面を整理し、エージェントに「ローカル LLM」「Python の生成と実行」「ディレクトリの操作」の能力を、管理ページのノードグラフで足せるようにする。

## 2. 要求と対応

| # | 要求 | 対応 | 段階 / 決定 |
|---|---|---|---|
| A1 | ポータルのトレース画面を削除し、一時表示のターミナル窓に表示する（既存機能を使う） | トレースのパネルを廃止。ターミナル窓（ADR 0033）がその役を担う | 第 1 段階。ADR 0036 |
| A2 | `icons/Cat_Symbols_Reference_24px/svg` の一般的なアイコンを UI の適所に使う | 27 個を `web/public/ui-icons/` に置き、主要なボタンに反映 | 第 1 段階。ADR 0036 |
| B1 | ローカル LLM を実行するプラグイン的なエージェント。Docker で動く LLM を、Claude の Haiku の代わりに使える | **別セッション型**: Docker のローカル LLM を Anthropic 互換の API で公開し、その接続先で `claude -p` を動かす委任先（`type: session`）として登録する | 第 4 段階（未着手） |

| B3 | エージェントにディレクトリを割り当て、参照・読み込み・書き込み・削除ができる。ノードグラフで管理 | 「ディレクトリ」ノード（1 ノード 1 ディレクトリ、作業領域 `workspace/` の中）を、ツールとして担当につなぐ。権限（参照・読み込み・書き込み・削除）はチェックボックス、既定はすべてオフ。強制は Agent Console（権限がオンの操作だけを公開し、`canUseTool` で担当の接続も確認） | 第 2 段階（実装済み）。ADR 0037 |

## 4. 制約
- 使うライブラリは商用利用できる許諾（MIT / Apache-2.0 / BSD など）のものにする。
- Azure のリソースを作成・変更・削除する操作は行わない（既存の方針）。

## 5. 未確認・リスク
- 第 4 段階: Docker のローカル LLM が Anthropic 互換の API を出せるか、ツール呼び出しにどこまで対応するかは、実装時に確認する。ローカルの小型モデルは、ツールを使う長い作業に弱いことが多い。
- 第 3 段階: 生成したコードの実行は、コンテナを破られた場合の影響が大きい。ネットワークなし・非 root・読み取り専用のファイルシステム・実行時間とメモリの上限を必須とする。
- 第 2 段階: 削除の権限は、データを失う操作。既定はすべてオフ。書き込み・削除つきのノードを新しくつなぐときは確認が要る。削除はファイルと空のフォルダだけ（再帰削除なし）。権限はノード単位で、つないだ全担当に同じに効く。猫神さま自身と、別セッション型の委任先には使えない。
- 第 1 段階: 小さなアイコン（18〜20px）は、猫の細部が潰れて判別しにくい。名前の文字を必ず併記している。
