# 0043 担当を呼ぶ接続と、担当の自動作成

- 状態: Accepted
- 関連: [0040](0040-llm-node.md)、[0041](0041-python-node.md)、[0042](0042-nested-suborchestrators.md)、要件 [rev2](../requirements/20261025-rev2-llm-node-tree-dynamic-agents.md)（5、6(b)）

## 背景
- 要求 6(b): `py-analyst` のような担当を、ほかの担当がツールとして使えるようにしたい（猫神さまだけでなく）。
- 要求 5: サブオーケストレーター配下の担当で足りないと判断したとき、(1) 自動で担当を作り、処理が終わったら削除する。(2) 自動作成の担当を、トレースとポータルのターミナルで分かるようにする。

## 決定
### 担当を呼ぶ接続（担当 → 担当）
- 担当の下のピンから、呼ばれる担当の上のピンへワイヤーでつなぐ（親子の左右のピンとは別）。台帳に `callee_ids` を持つ。
- つなぐと、呼ぶ側の定義ファイルの `tools` に `Agent` を足す（なければ）。呼ぶ仕組みは、Claude の `Agent` ツールと入れ子（0042）をそのまま使い、新しい実行役は作らない。深さの上限（4 階層）が効く。
- 拒否するもの: 自分自身、猫神さま（委任先一覧で管理）、定義ファイルのない担当、呼び合いの輪（A → B → A）。呼ばれる担当を消すと接続も外れる。
- 呼ぶ側が呼ばれる担当を知る手がかりは、`Agent` ツールの担当一覧（`.claude/agents/` の定義の説明）。プロンプトは書き換えない。

### 担当の自動作成
- **スイッチ**: サブオーケストレーターごとに、管理ページのインスペクタで「足りないとき、担当を自動で作ってよい」を入れる（既定はオフ）。入れると定義の `tools` に `mcp__neko-spawn__*` が入り、切ると消える。定義ファイルのあるものだけ。
- **仕組み**: Agent Console が MCP ツール `spawn`（`neko-spawn` サーバー）を持つ。呼ばれると、Agent SDK の入れ子の `query` で**使い捨ての担当**を動かし、結果を返す。担当の定義は**保存しない**（ファイルも台帳も作らない）ので、終わった時点で消える。
- **制限**（決定済み）:
  - ツールは読み取り系の `Read / Glob / Grep / WebSearch / WebFetch` だけ。呼んだ担当がつないでいる読み取り系のツールのうち引き継げるものだけを使う（つながっていなければ、作れない）。書き込み・実行・Agent（ほかの担当を呼ぶ）・ノードは引き継がない。
  - 1 回の依頼（チャットの応答）で最大 **3 体**。
  - 最大 12 ターン、180 秒で止める。ユーザーの中断で止まる。プロジェクトの設定・フック・MCP は読まない。モデルは `SPAWN_MODEL`（既定 haiku）。
- **許可の確認**: 呼ぶたびに、呼んだ担当が `mcp__neko-spawn__*` を持つことを確かめる（0037・0040 と同じ）。呼んだ担当の名前とツールは、許可の処理が入力へ書き込む（モデルが指定した値は上書きされる）。特定できなければ拒否。
- **見える化**: 自動作成の担当の動きを、フックと同じ形のイベントで送る。`agentType` は `自動作成/<名前>`、`auto: true` つき。トレースのパネル（ターミナル）、Agent Console のタイムライン、フロー図に、「自動作成して開始」「ツール呼び出し」「完了（自動作成の担当を削除）」と出る。

## 理由
- 担当を呼ぶのは、既存の `Agent` ツールで足りる。新しい仕組みを増やさない。
- 自動作成を `query` の入れ子にしたのは、Claude Code のサブエージェント定義がセッション開始時に決まり、途中で足せないため。ツールとして結果を返す形なら、呼んだ担当が普通のツール呼び出しとして扱える。
- 読み取りだけ・3 体まで・スイッチで許可制にすることで、勝手に増える・壊す危険を抑える。

## 影響・注意
- 自動作成のたびに、別のモデル呼び出し（費用）が増える。スイッチは必要なサブオーケストレーターだけに入れる。
- 自動作成の担当は、呼んだ担当の会話の文脈を持たない。依頼（`task`）に前提・目的・期待する出力を書かせる。
- 実機で、`e2e-sp`（スイッチ入り）が `自動作成/readme-reader` を作り、Read で調べさせ、結果を受けて削除するまで、トレースに出ることを確認した。
- 担当 → 担当の接続は、「呼べる」ことを許すだけで、呼ばせる強制はしない（`Agent` ツールの一般の挙動）。
- 試験: 許可・引き継ぎ・作成と削除・失敗・3 体の上限（Console）、スイッチ・接続・拒否・削除時の外れ（API）、ピンの向き・拒否（画面）。
