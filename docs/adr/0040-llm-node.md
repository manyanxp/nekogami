# 0040. LLM ノード（ローカル LLM を、担当へつなぐツールにする）

- 状態: Accepted
- 日付: 2026-10-25

## 背景
rev2 の要求: ローカル LLM を、他のサブオーケストレーター・エージェントから呼べるようにしたい。ノードで接続できること。Claude のモデル表示は不要で、ローカル LLM の名称を出したい。プロンプトをチューニングできる編集欄がほしい。

[0039](0039-local-llm-agent.md) の `local-llm` は、`claude -p` を別セッションで動かす委任先で、猫神さまだけが呼べた。他の担当から呼ぶには、ノードにはなっておらず、Claude Code のプロンプト（約 8K トークン）が 16K の文脈を圧迫する。

## 決定
- **LLM ノード**: ツールの一種 `kind: llm`。持つ値は `model`（Ollama のモデル名）、`prompt`（システムプロンプト、8000 文字まで）、`temperature`（0〜2、既定 0.7）、`max_tokens`（16〜4096、既定 1024）。台帳に保存する。
- **公開のしかた**: Agent Console が、ノードごとに Agent SDK のプロセス内 MCP サーバー `llm-<名前>` を作り、`ask` ツール（引数 `prompt`、任意の `context`）を 1 つ公開する。呼ぶたびに、台帳から読み直す（編集は次の質問から効く）。
- **Ollama を直接呼ぶ**: `POST {OLLAMA_URL}/api/chat`（既定 `http://ollama:11434`）。`stream: false`、`think: false`（考える過程を出さず、答えだけ返す。速い）。履歴は持たず、1 回ごとの質問。
- **接続**: ディレクトリのノード（[0037](0037-directory-nodes-and-permissions.md)）と同じ。担当の定義ファイルの `tools` に `mcp__llm-<名前>__*` が入る。Agent Console は、呼ばれるたびに、ノードが台帳にあり、**呼んだ担当が接続している**ことを確かめる（特定できなければ許可しない）。確認ダイアログは要らない（外への書き込みも実行もなく、手元の Ollama に文章を送るだけ）。
- **接続できる相手**: ツールを書ける担当だけ。API が、つなぐ前に確かめる（ディレクトリのノードにも同じ検査を入れた）。
  - 定義ファイル（`.claude/agents/`）のあるエージェント・サブエージェントは、自分自身の定義に書く。
  - **サブオーケストレーター**は、委任先（`suborchestrators.json` で `type: agent` のもの）の担当の定義に書く。`azure-sage` と話すとき、実際に動くメインスレッドは委任先の `azure-architect` なので、サブオーケストレーターへの接続は、その担当のツールになる。外すと、その項目が消える。書き込み・削除・Python 実行つきのディレクトリは、ここでも確認が要る。
  - 猫神さま（`CLAUDE.md`）や、委任先のないサブオーケストレーターは、つないでも実行時に効かないので、登録時に拒否する。
  - 注意: サブオーケストレーターへつないだノードは、委任先の担当（`azure-architect` など）を直接呼んでも使える（同じ担当だから）。
- **上限**: 質問と資料の合計 24,000 文字、答え 20,000 文字（切り詰める）、待ち 180 秒。
- **名称の表示**: ノードは「ローカル LLM · モデル名」を表示し、Claude のモデル選択を持たない。委任先の登録ダイアログも、ローカル LLM の委任先（`env` に `ANTHROPIC_BASE_URL` がある session 型）では、Claude のモデル選択の代わりに、モデル名を出す。
- **プロンプトの編集**: 管理ページで LLM ノードを選ぶと、モデル名・プロンプト（編集欄）・温度・出力の長さを編集できる。
- **`local-llm`（別セッション型）は残す**: ファイルの読み取りが要るときは、こちらを使う。

## 検証
- 試験: ノードの検証・接続・定義ファイルへの反映・削除、サブオーケストレーター経由の接続（API）、`ask` の引数、設定の渡し方、上限、エラー、接続の確認（Console 5 件）、画面のモデル。
- 実機: 確認用の担当に `mcp__llm-<名前>__ask` をつなぎ、実際の Claude から呼んだ。ローカルの `qwen3:8b` が、ノードのプロンプト（語尾に「にゃ」）に従って「東京タワーは333メートルにゃ。」と答え、担当が引用して報告した。猫神さまへの接続は、拒否された。確認用のものは片付けた。

## 影響・注意
- **不具合の修正（同時）**: 管理ページでサブオーケストレーターを選ぶと、「定義ファイルを読めない: /project/CLAUDE.md」と出た。`azure-sage` の定義はプロジェクト直下の `CLAUDE.md` だが、3 コンテナに分けたとき（[0034](0034-frontend-backend-containers.md)）、`api` コンテナに渡し忘れていた。`./CLAUDE.md` をマウントし、ファイル単体のマウントは rename で置き換えられない（EBUSY）ため、その場で書き直すようにした。
- LLM ノードは会話だけで、ツールもファイルも使えない。読めるのは、渡した文章だけ。
- Ollama が起動していないと、`ask` は「接続できない」と返し、起動のしかたを案内する。
- ノードを消すと、担当の定義ファイルの接続も外れる（[0038](0038-python-execution-sandbox.md) と同じ）。
