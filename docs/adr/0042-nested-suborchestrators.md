# 0042 サブオーケストレーターの入れ子（ツリー構成）

- 状態: Accepted
- 関連: [0016](0016-agent-definition-files.md)（定義ファイルの置き場）、[0017](0017-suborchestrator-as-agent-definition.md)、[0040](0040-llm-node.md)、要件 [rev2](../requirements/20261025-rev2-llm-node-tree-dynamic-agents.md)（2）

## 背景
rev2 の要求 2: サブオーケストレーターにもオーケストレーターを接続し、ツリーで構成したい。これまでサブオーケストレーターは猫神さまの直下にしか置けなかった。

## 決定
- **親にできる種別**: サブオーケストレーターの親に、別のサブオーケストレーターを許す（猫神さま → A → B → …）。管理ページでは、ほかの親子と同じく、出力ピンから入力ピンへワイヤーでつなぐ。
- **深さの上限は 4 階層**（猫神さまを 0 とする。猫神さま → A → B → C → 担当）。ポータルの検査（`MAX_DEPTH`）と、実行時の `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=4`（neko-brain の環境変数）を揃える。循環（子孫を親にする）も拒否する。
- **入れ子にできる条件**（付ける・付け替えるときに検査する）:
  - 親と子の両方が、定義ファイル（`.claude/agents/` の `role: suborchestrator`）を持つ。Claude が親から子を呼ぶのは、親の `Agent` ツールで、子の定義が要るため。`azure-sage`（`CLAUDE.md`）や `news-sub`（定義なし）は、入れ子にできない。
  - 親の `tools` に `Agent` がある（ない場合は先に足す）。
- **ファイルの置き場所**: 入れ子のサブオーケストレーターは、**親のフォルダ**に置く（`.claude/agents/<親>/<自分>.md`）。親が `Glob` で配下を探すと見つかるため。自分の配下は、これまでどおり自分の名前のフォルダ（`.claude/agents/<自分>/`）。猫神さま直下のものは、自分の名前のフォルダ（`<自分>/<自分>.md`）のまま。付け替え・名前の変更では、ファイルとフォルダを一緒に動かす。
- **委任先一覧**（`suborchestrators.json`）には、**猫神さま直下のものだけ**を載せる。入れ子になった（外れた）ときは、自動で外す（戻したときは載せる）。猫神さまが直接呼ぶのは直下だけで、その下は、親が呼ぶ。
- **同期**: 定義ファイルから台帳を組み立てるとき、`role: suborchestrator` のファイルが、別のサブオーケストレーターのフォルダにあれば、入れ子として読む。
- **ノードの接続**: 入れ子のサブオーケストレーターは定義ファイルを持つので、ディレクトリ・LLM・Python のノードは、その定義の `tools` に書かれる（0040）。実行時の担当の特定は、サブエージェントの ID で行うので、深くなっても同じ。

## 理由
- 親が配下を `Glob` で見つけ、`Agent` ツールで呼ぶ今の作りを、そのまま入れ子に使える。新しい呼び出しの仕組みは要らない。
- 深さを実行時とポータルで揃えないと、ポータルで作れても実行時に呼べない（またはその逆）ツリーができる。

## 影響・注意
- 深い入れ子は、費用と時間が増える（1 段ごとに別のモデル呼び出し）。上限は 4 階層。
- `Agent` ツールの呼び出しは、背景で動くことがあり、親の応答が先に終わることがある（実機で確認）。依頼文で「結果を待って」と書く。
- 実機で、猫神さま直下の `e2e-top` → `e2e-mid` → `e2e-leaf` → Python ノードの呼び出しが通ることを確認した。
- 試験: 置き場所・委任先・深さ・循環・付け替え・名前変更・条件（API）、接続可否と親の選択肢（画面）。
