# 0013. 管理者エージェント（猫神さま）の保護と管理ページ

- 状態: Accepted
- 日付: 2026-10-24

## 背景
Phase 3 の要求 Q1〜Q5。猫神さまは全体の要で、台帳から消えると階層とチャット・委任の前提が崩れる。一方、ポータルの一覧は日常の操作（サブオーケストレーター以下）に絞りたい。

## 決定
- **保護**: エンティティに `protected` フラグを持たせ、組み込みの `nekogamisama` だけを `true` にする。
  - バックエンド（`registry.py`）が拒否する（HTTP 403）: 削除（子ごとの `cascade` を含む。子の有無の検査より先に判定）、無効化、改名、親の変更。
  - `protected` は API の作成・更新で受け付けない（無視する）。UI を迂回しても外せない。
  - 説明・モデル・タグ・配置は編集できる。
  - Phase 2 の台帳は `sync-builtin`（ポータル起動時にも実行）で `protected` が付く。
  - 注意: 台帳ファイル（`portal/data/registry.json`）を直接編集すれば消せる。守る対象は API と UI。
- **管理ページ**: `/admin.html`（フロントの別ページ、同じバックエンド）。
  - 猫神さまの状態、種別ごとの件数、説明・モデルの編集。
  - 委任先の突き合わせ: `GET /api/admin/overview` が、台帳のサブオーケストレーターと `nekogamisama/suborchestrators.json` を突き合わせ、「台帳に無い」「委任設定に無い」を示す。**読み取りのみ**（ポータルが委任先の設定を書き換えると、委任でコマンドを動かすフォルダを間接的に変えられるため、書かない）。
  - ノードグラフ（[ADR 0014](0014-node-graph-editor.md)）。
- **ポータルの一覧**: `protected` を一覧に出さず、その子を最上位として表示する（猫神さまは管理ページの担当）。件数表示も猫神さまを除く。
- **ツリーのトグル**: 子を持つ行に ▼/▶。折りたたんだ親の ID は `localStorage` に保存（使えない環境でも動く）。「展開」「折りたたみ」で一括。検索・種別フィルタ中は折りたたみを無視する。
- **移動**: ポータルのヘッダーに管理ページへのリンク、管理ページに戻るリンク。

## 理由・検討した代替案
- フロントだけで削除ボタンを隠す案: 他の API クライアントから消せるので不採用。サーバー側で拒否する。
- 猫神さまを一覧にも出して、削除だけ無効化する案: 要求（一覧はサブオーケストレーター以下）に反するので不採用。
- 管理ページから `suborchestrators.json` を編集する案: 上記の理由で不採用。不一致を見せて、手で直してもらう。

## 影響
- 良い点: 猫神さまの誤削除を API 層で防げる。日常の一覧が見やすい。
- 制約: 保護は 1 件（組み込みの猫神さま）が前提。保護対象を増やす場合は同期処理を足す。
