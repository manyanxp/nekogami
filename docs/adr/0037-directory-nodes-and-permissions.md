# 0037. ディレクトリのノードと権限（担当が読み書き・削除できる作業領域）

- 状態: Accepted
- 日付: 2026-10-25

## 背景
rev1 の要求: 担当に指定したディレクトリを、参照・読み込み・書き込み・削除できるようにしたい。ディレクトリは 1 ノードにつき 1 つ用意し、ツールとして担当へ自由につなぐ。参照・読み込み・書き込み・削除は、チェックボックスの権限で指定する。管理ページのノードグラフで管理する。

## 決定
- **ノード**: ツールの一種として `kind: directory` を足す。持つ値は `path`（作業領域からの相対パス）と `perms`（`list` 参照 / `read` 読み込み / `write` 書き込み / `delete` 削除。**既定はすべてオフ**）。台帳（`portal/data/registry.json`）に保存する。
- **作業領域**: プロジェクトの `workspace/`（Agent Console の `FS_ROOT`、compose でホストの `./workspace` をマウント）。ノードの `path` はこの中に限る。絶対パス・`..`・バックスラッシュ・`.` で始まる名前・9 階層以上は、登録の時点で拒否する。中身は利用者のデータなので、Git には入れない。
- **ノード名**: 英数字とハイフンだけ（40 文字まで）。MCP のサーバー名（`dir-<名前>`）になり、記号は置き換えられうるため。
- **公開のしかた**: Agent Console が、ノードごとに Agent SDK のプロセス内 MCP サーバー `dir-<名前>` を作り、**権限がオンの操作だけ**をツール（`list` / `read` / `write` / `delete`）として公開する。チャットの開始ごとに台帳を読み直すので、権限の変更は次のチャットから効く。
- **接続**: ノードを担当につなぐと、担当の定義ファイルの `tools` に `mcp__dir-<名前>__*` が入る。Claude Code は、`tools` にあるツールだけをその担当に見せる。
- **二重の確認（`canUseTool`）**: 呼ばれるたびに、Agent Console が (1) ノードの権限、(2) 呼んだ担当が接続されているか、を確かめる。呼んだ担当は、`canUseTool` の `agentID` と、`SubagentStart` のフックで覚えた「ID → 担当名」で特定する。特定できない・`tools` を指定していない（全ツールを継承する）担当は、**許可しない**（安全側）。
- **場所の検査**（`dashboard/fs-tools.mjs`）: 実体のパス（`realpath`）が、ノードのディレクトリの中にあることを、毎回確かめる。シンボリックリンクで外へ出る読み・書き・一覧は拒否。リンクの削除は、リンクだけを消す。
- **操作の範囲**: 一覧は直下（`path` 指定で下位）。読み込みは先頭 200 KB まで。書き込みは 1 MB まで（上書き、親フォルダは作る）。削除はファイルと**空のフォルダだけ**（再帰削除はない）。ノード自体は削除できない。
- **危険な接続の確認**: 書き込み・削除が付いたディレクトリを、担当に**新しく**つなぐときは、管理ページで確認を求め、API も確認（`allow_dangerous`）がないと拒否する（`Write` / `Bash` と同じ扱い）。すでにつないであるノードの権限を広げるときも、つないである担当を示して確認する。
- **画面**: 管理ページのツールバーに「ディレクトリ」、ノードの下に「場所・権限」を表示。選択すると場所と権限をチェックボックスで編集できる。

## 検証
- 試験: 場所の検査・リンクによる脱出・権限・接続の確認（`dashboard/fs-tools.test.mjs` 9 件）、台帳の検証と危険な接続の確認（API の試験）、画面のモデル（vitest）。
- 実機: 確認用の担当とノード（参照・読み込み・書き込みのみ）を作り、実際の Claude で依頼。書き込み・一覧・読み込みができ、削除用のツールは公開されず、担当は「削除用のツールがない」と報告した。確認用のものは片付けた。

## 影響・注意
- **猫神さま自身（指揮役）には使えない**: 指揮役の定義は `CLAUDE.md` で、`tools` を持たない。ノードをつないでも、台帳の情報にとどまる。
- **別セッション型の委任先（`delegate.sh`）は対象外**: `claude -p` は別のプロセスで、Agent Console のプロセス内サーバーを持たない。
- 権限は**ノード単位**で、つないだすべての担当に同じに効く。担当ごとに権限を変えたいなら、ノードを分ける。
- `workspace/` は Agent Console がホストと同じユーザーで書き込む。重要なファイルを置かない。バックアップは取らない。
- 依存の追加: `zod`（MIT。Agent SDK の peer 依存で、ツールの引数の定義に使う）。
