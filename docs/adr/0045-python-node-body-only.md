# 0045 Python ノードは「処理だけ」を書く（関数は入力ノードから自動生成）

- 状態: Accepted（[0041](0041-python-and-input-nodes.md) の「関数ごと書く」を置き換える。旧形式は互換のため残す）
- 関連: [0044](0044-admin-ui-and-subagent-persona.md)、要件 [rev3](../requirements/20261025-rev3-admin-ui-and-persona.md)

## 背景
0041 では、Python ノードに関数（`def main(x: int): ...`）ごと書き、入力ノードは「関数に同じ名前・型の引数があるときだけ」つなげた。このため、引数を書く前に入力ノードをつなげず、「入力ノードが接続できない」不具合になっていた。

## 決定
- コード欄には**処理（関数の中身）だけ**を書く。関数名・引数は書かない。結果は `return` で返す。
- **引数は、つないだ入力ノードから自動で決まる**。入力ノードの引数名・データ型・値が、そのまま関数のパラメータ（名前・型・既定値）になり、Python ノードのプロパティに読み取り専用で表示される。入力ノードの追加・変更・削除、つなぎ直しのたびに、API が引数を作り直す。
- 実行時に、API が `def main(<引数>):` ＋ 処理（1 段下げる）の関数のソース（`source`）を作り、Console がそれを実行する。入力ノードの値は引数の既定値で、担当が渡せば優先（0041 と同じ）。
- 検査（保存時）: 処理が空でないこと、生成した関数が構文として正しいこと（エラーは処理の行番号で返す）、引数名が重複しない・Python の予約語や `__neko` で始まる名前でないこと。
- 結果は、処理が終わってから、呼んだ親（担当）へ返す（`run` は完了まで待つ同期の MCP ツール）。`return` がなければ戻り値は null で、標準出力を返す。
- 互換: コードの先頭の階層に `def <関数名>(` がある既存のノードは `style: function`（旧形式）として従来どおり動く。入力ノードの検査も従来どおり。それ以外は `style: body`。台帳にない `style` は、読み込み時に判定して足す。

## 影響・注意
- 実行は 0038/0041 のサンドボックス（ネットワークなし・30 秒・512 MB）のまま。
- 試験: 引数の自動決定・更新・削除時の再計算、重複・予約語・空・構文エラーの拒否（API）、`highlightEdges`（画面）。
