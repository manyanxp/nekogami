# 0018. 委任先一覧の編集、右クリックメニュー、名前の変更

- 状態: Accepted
- 日付: 2026-10-24

## 背景
Phase 4 の追記要求 S4〜S6。[ADR 0016](0016-agent-definition-files.md)・[0017](0017-suborchestrator-as-agent-definition.md) では、ポータルが `suborchestrators.json` の `session` 型（フォルダを指す）を書かない、サブエージェントの改名はしない、としていた。要求により、この方針を一部変える。

## 決定
### 委任先の突き合わせで、台帳と委任設定を同時に編集する
- 管理ページの「委任先の突き合わせ」の表（台帳のサブオーケストレーター ∪ 委任設定の項目）に、「編集」（両方にある）または「整える」（片方にしかない）を置き、**1 つのダイアログで台帳と委任設定の両方**を編集する。
  - 台帳側: 登録する／しない、説明、モデル、有効。登録は「サブオーケストレーター、猫神さまの配下、定義ファイルなし」のエンティティを作る（`POST /api/entities`）。登録の解除は削除（`DELETE`）。**定義ファイルのあるもの、配下があるものは解除できない**（チェックを固定して理由を表示。定義ごと消すのはグラフの削除）。
  - 委任設定側: 登録する／しない、種類、呼ぶエージェント / 実行フォルダ、説明（以下の API）。
  - 片方にしかない行は、足りない側にチェックが入った状態で開く。保存すると、台帳 → 委任設定の順に適用する。途中で失敗したら、完了した分を表示して、ダイアログは開いたままにする。
  - 台帳だけを外しても、委任設定は残す（逆も同じ）。定義ファイルごと消えるサブオーケストレーターの削除だけは、従来どおり `type=agent` の項目も消す。
  - 概要 API（`GET /api/admin/overview`）の各行に、台帳側の要約（`entity`: 説明・モデル・有効・定義の有無・配下の数）と、`agent` が指す先（`target`）を含める。

### 委任先一覧（`nekogamisama/suborchestrators.json`）の編集
- API: `GET /api/delegation`、`PUT /api/delegation/{名前}`、`DELETE /api/delegation/{名前}`。管理ページの突き合わせの表から、追加・編集・削除ができる。
- 検証（バックエンド）:
  - `agent` 型: `agent` は `.claude/agents/` にある定義の `name` だけ。
  - `session` 型: 名前は小文字・数字・ハイフンのみ（`delegate.sh` の規則）。`dir` は **`nekogamisama/` からの相対で、プロジェクト配下の既存フォルダ**だけ（猫神さまがそこで `claude -p` を実行するため、プロジェクトの外やシステムのフォルダは拒否）。
  - `type` は `agent` / `session` のみ。説明は 300 文字まで。壊れた JSON は上書きしない（直すよう案内する）。
- 書き換えのたびに、元のファイルを `portal/data/backups/` へ退避し、一時ファイル + 置き換えで書く。
- ADR 0016 の「`session` 型はポータルから作らない・変えない・消さない」を、**画面から明示的に操作した場合に限って**変更する。サブオーケストレーターの追加・削除に伴う自動更新は、従来どおり `agent` 型だけを触る。

### 右クリックメニュー
- グラフ上の右クリック（`contextmenu`）を `graph.js` が拾い、`admin.js` がメニューを出す。
  - 背景: サブオーケストレーター / エージェント / サブエージェント / ツールの追加。クリックした位置に新しいノードを置く（`pos`）。
  - エンティティのノード: そのノードの配下に作れる種別の追加（親が入った状態で追加ダイアログが開く）、ツールの追加、名前の変更、削除（猫神さまは削除不可を表示）。
  - ツールのノード: ツールの追加、削除。ワイヤー: ツール接続を外す（親子のワイヤーは外せない）。
- メニューは画面の外へはみ出さず、メニューの外のクリック・Esc・ウィンドウのフォーカス喪失で閉じる。

### 名前の変更
- 対象: サブオーケストレーター・エージェント・サブエージェント（`PATCH /api/entities/{id}` の `name`）。猫神さまは不可（403）。
- 追随する項目:
  - 自分の定義ファイル: `name:` とファイル名（サブオーケストレーターは自分のフォルダも）。
  - 子の定義ファイル: 親の名前のフォルダへ移す（規則は ADR 0016）。
  - 委任先一覧: 項目のキー（`agent` 型で `agent` が自分の名前なら、その値も）。並び順は保つ。
- 先に衝突を調べ、何か 1 つでもぶつかれば、何も動かさずに拒否する（`.claude/agents/` 以下の定義の `name`、エンティティ名、移動先のパス）。移動前のファイルは `backups` に退避する。
- 他のエージェントのプロンプトや説明に書かれた名前は、自動では書き換えない（確認ダイアログで明示する）。

## 理由・検討した代替案
- `session` 型の `dir` を、ポータルから自由に指定できるようにする案: 任意のフォルダでコマンドの実行環境を決められるので、プロジェクト配下に限った。
- 改名を「作り直し」に任せる案: UUID・親子・ツール接続・位置が失われ、委任先一覧も手で直すことになる。要求にも反する。

## 影響
- 良い点: 委任先の追加・修正が画面で完結し、改名してもファイルと一覧が整合する。
- 制約・注意:
  - ポータルを操作できる人は、プロジェクト配下の任意のフォルダを `session` 型の実行場所にできる（ポータルは 127.0.0.1 限定・Host/Origin 検証・任意のトークンで守る。ADR 0008）。
  - 実行中のセッションがあるときに改名すると、そのセッションが古い名前を参照し続けることがある。
  - 改名後の旧名は、プロンプトの文面に残っていれば、指揮役が古い名前で呼ぶことがある。
