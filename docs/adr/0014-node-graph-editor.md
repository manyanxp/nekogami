# 0014. ノードグラフエディタ（自作 SVG）とツール接続の位置づけ

- 状態: Accepted（自作 SVG のグラフは [0031](0031-nextjs-fastapi-split.md) で @xyflow/react に置き換え）
- 日付: 2026-10-24（モデルの選択を追記）

## 背景
Phase 3 の要求 Q6: サブオーケストレーターとエージェントを、Unreal Engine の Blueprint のようなノードグラフで追加・削除し、ツールに接続したい。制約は、寛容なライセンスの採用と、ビルド不要の現行フロント構成（ADR 0007）。

## 決定
- **実装**: ブラウザ標準の SVG と Pointer Events による自作（`portal/frontend/js/graph.js`、純粋ロジックは `graph-model.js`）。追加ライブラリなし。
- **ノードと接続**:
  - ノード: エンティティ（猫神さま、サブオーケストレーター、エージェント、サブエージェント）とツール。ツールは台帳の新しい種類のデータ（`tools`）で、組み込みツール（Read など 8 種）と `.mcp.json` の MCP サーバーを自動登録し、`custom` を追加できる。
  - ワイヤー: 親 → 子（実線）とエージェント → ツール（黄の破線）。
  - ピン: 右の ● が出力、左の ● が入力。出力から入力へドラッグして接続する。猫神さまは入力ピンを持たない（親を持てない）。
- **操作**:
  - 接続: 子の入力ピンに親の出力ピンをつなぐと親の付け替え。エージェントからツールにつなぐとツール接続。可否は `canConnect()` で即座に判定し（種別の規則・循環・重複）、最終判定はバックエンド。
  - 追加: ツールバーで種別を選び、名前・親（選択中のノードがあれば既定）を入力。ツールも追加できる。
  - 削除: 選択して Delete キーか「選択を削除」。配下があれば確認のうえ一緒に削除。ツール接続のワイヤーも外せる。親子のワイヤーは単独では削除できない（親が必須のため）。猫神さまは削除不可。
  - 移動・パン・ズーム: ノードの位置は `pos` として台帳に保存。「自動整列」で破棄できる。位置が無いノードは深さと並び順で自動配置する。
- **データ**: エンティティに `tool_ids`（接続）と `pos`（配置）を追加。台帳ファイルは version 2（`tools` を持つ）。API は `GET/POST /api/tools`、`PATCH/DELETE /api/tools/{id}`。ツールを削除すると接続も外れる。
- **モデルの選択**: 選択したエンティティの詳細と追加ダイアログに `<select>`（`graph-model.js` の `MODEL_CHOICES`）。別名（`inherit` / `haiku` / `sonnet` / `opus`）とフルのモデル ID。現在値が選択肢にない場合は消さずに選択肢へ加える。台帳の `model` に保存する。
  - **ツール接続と同じく台帳上のメタ情報**で、実際に使われるモデルは定義ファイル（`.claude/agents/*.md` の `model:`、猫神さまは `nekogamisama/.claude/settings.json`）。組み込みサブエージェントで台帳と定義ファイルが食い違うと、`/api/admin/overview` の `drift` と詳細パネルの警告で示す。
> **更新（Phase 4）**: 定義ファイルのあるエンティティでは、ツール接続とモデルの選択は**実際の定義ファイルへ書き込まれる**（[ADR 0016](0016-agent-definition-files.md)）。以下の「メタ情報」は、定義ファイルのないエンティティ（Docker などで外部管理）にだけ当てはまる。
- **ツール接続はメタ情報**: 台帳に記録するだけで、`.claude/agents/*.md` の `tools:` や実際の権限は変えない。組み込みのサブエージェントは、初回の取り込み時に `tools:` の記述から初期接続を作る（その後に利用者が外した接続は復活させない）。

## 理由・検討した代替案
- React Flow（MIT）などのライブラリ: React とビルド工程が必要になり、現行構成（ビルド不要、依存ゼロ）と合わない。litegraph.js は Blueprint に近いが、DOM 外の Canvas 描画で、日本語やアクセシビリティの扱いが重く、取り込みのサイズと保守が過剰。個人利用の規模（数十ノード）では自作で足りる。
- ツール接続・モデル選択でエージェント定義ファイルを書き換える案: 実際の権限を変える操作で、レビューなしにファイルを書き換えるのは危険。将来、差分確認つきの書き出しとして別途検討する。

## 影響
- 良い点: 依存なし、ライセンス確認不要。ノード・接続の規則がテストできる純粋ロジックに分かれている。
- 制約・注意:
  - 数百ノードを超える規模は想定しない（毎回全ノードを再描画する）。
  - グラフ上の変更は台帳（`registry.json`）にだけ反映される。実際のエージェントの構成は変わらない。
  - キーボードだけでの操作は未対応（削除は Delete のみ）。
- 確認: `portal/frontend/test/`（`/test/` を開くとブラウザ内でロジックと合成ポインター操作のテストが走る）。ヘッドレス Edge で 42 項目が通過。
